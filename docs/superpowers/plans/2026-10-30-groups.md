# Groups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add groups (separate boards, shown as tabs). Each group has its own pads and shortcuts, and only the selected group's shortcuts are live.

**Architecture:**
- `Config` replaces its flat `pads` list with `groups: Vec<Group>` plus a `selected_group` index.
- Pad lookups by id search every group. Pad ids stay globally unique.
- `config::load` migrates an old flat file into a "Main" group, writing a one-time backup first.
- `hotkeys::bindings` registers only the selected group's pads plus Stop and Go Live.
- The engine still gets every pad, so a sound keeps playing across a tab switch.
- The UI adds a tab row and small modals for new, rename and delete.

**Tech Stack:** Rust 2024, eframe/egui 0.37, serde/serde_json, global-hotkey 0.9, tempfile (tests).

**Spec:** `docs/superpowers/specs/2026-10-30-groups-design.md`

## Global Constraints

- **Work on `develop`.** Every task ends with `make check` passing (fmt check, clippy `-D warnings`, `cargo test --lib --bins`).
- **TDD:** each change starts with a failing test.
- **The first-group name is exactly `Main`.** A fresh install and a migrated old file both get it.
- **The backup file is `config.json.pre-groups`,** next to `config.json`. It's written only when migrating, and only if it doesn't already exist.
- **Group names** are trimmed, non-empty, and unique ignoring case.
- **Delete prompt copy:** `Delete “{name}” and its {n} sounds? The audio files stay on your PC.` Use `1 sound` for one. An empty group is deleted without a prompt.
- **Conflict copy:**
  - for a pad in another group: `{key} is already used by “{pad}” in {group}.`
  - otherwise, the existing `{key} is already used by “{pad}”.` / `… by Stop.` / `… by the Go Live switch.`
- **Release:** don't bump the version or release. Releasing is the owner's call (v0.5.0 when they do).

## Review Focus

1. **Downgrade, then upgrade again.**
   - An old version rewrites `config.json` with flat `pads` and no groups. The next upgrade migrates again.
   - The original `.pre-groups` backup must **not** be overwritten.
   - Test: `migration_keeps_existing_backup` (Task 2).
2. **Deleting a group that isn't selected.**
   - The selection must stay on the same group, even though its index shifts.
   - Test: `delete_before_selected_keeps_selection` (Task 3).
3. **Renaming a group to a different case of its own name** (Gaming → gaming) must be allowed, not reported as a clash with itself.
   - Test: `rename_to_own_name_in_other_case_is_allowed` (Task 3).
4. **Hidden autostart registers the remembered group's shortcuts,** not group 0's.
   - Test: `bindings_follow_selected_group_after_reload` (Task 4).
5. **Deleting a group whose pad is playing** must stop it and clear that group's pad errors.
   - Test: `delete_group_stops_its_playing_pad` (Task 5).

### Task 2: Migrate old files, with a one-time backup, and repair broken group data

**Files:**
- Modify: `src/config.rs` (`load`, `normalize`, tests)

**Interfaces:**
- **Consumes:** Task 1's `Config.legacy_pads`, `groups` and `FIRST_GROUP`.
- **Produces:** `pub fn pre_groups_backup_path(config: &Path) -> PathBuf`, which returns `config.json.pre-groups` next to `config`. It's used only in tests and the README.

**Behaviour:** in `load`, after a successful parse and before `normalize`:
- **If `cfg.legacy_pads.take()` is `Some(pads)`** (an old-format file):
  1. If the backup path doesn't exist, write the original `bytes` to it (ignore errors).
  2. Set `cfg.groups = vec![Group { name: FIRST_GROUP.into(), pads }]`, `cfg.selected_group = 0` and `cfg.version = 2`.

**`normalize` repairs:**
1. Empty `groups` → one empty `Main` group.
2. `selected_group` out of range → 0.
3. Duplicate pad ids across all groups: give the later duplicates fresh ids from `max_id + 1` upward, and set `next_pad_id` past them.
4. Group names: trim them.
   - An empty name becomes `Group {n}`, where n is its 1-based position.
   - A name that clashes (ignoring case) with an earlier one gets ` 2`, ` 3`… appended until it's unique.

### Task 3: Group operations on `Config`

**Files:**
- Modify: `src/config.rs`

**Interfaces:**
- **Produces:**
  - `Config::check_group_name(&self, name: &str, except: Option<usize>) -> Result<String, String>`:
    - `Ok(trimmed)`;
    - `Err("Enter a name.")` when the name is empty after trimming;
    - `Err("There's already a group called “{existing}”.")` when it clashes, ignoring case, with any group other than `except`.
  - `Config::add_group(&mut self, name: String) -> usize`: appends the group, selects it, and returns its index. Callers have already checked the name.

    - returns `None` (and does nothing) if it's the only group or the index is out of range;

      - if the selected group was after the deleted one, the index drops by 1;
      - if the selected group was deleted, the selection moves to the group that took its place (or to the new last group).
  - `Config::select_group(&mut self, index: usize) -> bool`: false if the index is out of range or the group is already selected.

  - `pub fn tabs(app: &mut SoundboardApp, ui: &mut egui::Ui)`:

    - clicking a tab calls `app.select_group(i)`;
    - `+` opens `New` (hover text "New group");
    - each tab's `context_menu` has Rename and Delete:
      - Delete is `add_enabled(groups.len() > 1, …)`;
      - Delete calls `delete_prompt`: `None` deletes right away, `Some` opens `Delete`.
  - `pub fn dialog(app: &mut SoundboardApp, ctx: &egui::Context)`:
